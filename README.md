# QQ 名片点赞插件

兼容 NapCat 与 SnowLuma 适配器，通过命令给 QQ 用户名片点赞。AI 工具可以生成命令，由用户发送后执行。

当前版本：1.0.0 正式版。

## 安装与升级

1. 安装 MaiBot 以及 NapCat 或 SnowLuma 适配器。
2. 将插件文件放入 plugins 下的独立插件目录。
3. 在 WebUI 插件配置中填写管理员 QQ 并启用插件，重启机器人。

首次从旧版本升级时，先完整停止机器人并等待已有请求结束，备份配置和数据后替换文件。旧版本未保存的在途请求无法从 JSON 中恢复；不要让旧版与新版同时发送。新版实例之间通过数据库事务协调额度，旧实例晚返回也不会覆盖新实例记录。

## 命令

- /赞 @张三：给张三提交默认次数的点赞。
- /赞 @张三 5：指定 5 次。
- 回复目标的消息发送 /赞：给被回复者点赞。
- /赞 123456789 5：直接指定 QQ 和次数。
- /点赞、/zan：与 /赞 相同。

命令只解析本次原始文本开头，不执行引用里的旧命令或正文里的用法示例。@昵称中的数字不会被当作 QQ 或次数。

次数必须为 1 至配置上限的 ASCII 整数。明确指定的 0、负数、小数、超限次数和多份次数均拒绝执行。一次只能指定一个目标；显式目标无效、被配置禁用或为机器人自身时直接拒绝，不会改给被回复者点赞。日额度不足时，仅提交剩余额度。

QQ 号按规范化后 5 至 12 位数字校验；前导零与 Unicode 十进制数字会归并为同一个 QQ 号，额度、权限比较及发送参数使用同一规范。

## AI 工具

已检查的 MaiBot 工具桥接会混合模型参数和宿主上下文，群聊调用还可能缺少实际发言者。插件无法仅凭这些字段判断身份来源。因此工具只生成命令，用户发送命令后才核验身份并执行；不接受模型填写的 user_id、message 等字段作为管理员凭据，也不会绕过公开模式的用户冷却。

等待用户命令确认与工具失败均明确返回 success=false。省略次数时使用当前配置；点满时通过 use_maximum=true 使用配置中的单次上限。不从未经核验的文字中猜测次数。无需修改 MaiBot 主程序。

## 配置

配置由 SDK/Runner 管理，可以在 WebUI 修改。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| plugin.enabled | true | 启用插件 |
| plugin.config_version | 1.0.0 | 配置版本，请勿手动修改 |
| like.default_times | 10 | 缺省次数；高于 max_times 时使用 max_times |
| like.max_times | 20 | 单次上限，范围 1 至 20 |
| like.daily_limit_per_target | 30 | 每目标每日上限，范围 1 至 50 |
| like.cooldown_seconds | 30 | 每发送者冷却秒数，0 表示关闭，最大 3600 |
| like.allow_at_target | true | 允许结构化 @ 指定目标 |
| like.allow_reply_target | true | 允许回复消息指定目标 |
| like.allow_raw_qq | true | 允许直接输入 QQ |
| like.enable_llm_tool | true | 启用 AI 命令提示，不直接发送点赞 |
| admin.admin_only | true | 只允许配置的管理员使用 |
| admin.admins | 空 | 管理员 QQ，逗号分隔，支持 qq: 前缀 |

默认启用管理员限制。管理员列表为空时，任何人都不能点赞；关闭管理员限制后，仍须识别真实命令发送者并执行冷却。

## 适配器

- 插件先通过 api.get 查询可见的登录和点赞接口，缺少接口时检查另一种命名空间，不用试发点赞来探测接口。
- 支持 adapter.snowluma 与 adapter.napcat，SnowLuma 使用版本 1，NapCat 使用宿主默认版本。
- 每次发送前重新查询当前登录 QQ。无法取得登录信息时停止发送；新版宿主提供消息所属 account_id 时，还会核对适配器账号。
- 点赞使用本次查询到的适配器。超时、断线或业务失败不会切换接口重发。

## 数据与异常处理

数据保存在 SDK 提供的插件 data_dir，账本文件为 like_ledger.sqlite3。使用 Python 标准库 SQLite，无需安装额外数据库服务。首次加载自动迁移旧 like_state.json，合并 QQ 别名额度、保留最晚冷却时间，旧 JSON 原样保留。

发送前必须成功落盘预占。超时、取消、断线、未确认的适配器结果及发送后结算失败，均保留本次额度；即使重启或跨日，也不自动释放或重发。已确认请求计入完成当天，正常完成的日额度按机器人所在机器的本地日期重置，冷却不会在午夜清空。

未确认记录持续占用对应目标额度，直至维护者根据日志核对；插件不提供一键清空。排查时先停机备份数据库，结合请求 ID 和适配器日志确认执行情况。删除账本会丢失防重与额度历史，不能用重启代替核对。旧 JSON 或账本损坏、迁移失败时暂停发送；写盘失败明确反馈，不按空额度继续。

回复中的提交次数表示发给 QQ 的请求参数，不保证实际到账次数；实际结果以 QQ 为准。

## 兼容范围与测试边界

- MaiBot：1.2.0 至 1.3.99。
- maibot-plugin-sdk：2.7.1 至 2.99.99，同时须满足所用主程序自身的 SDK 依赖；MaiBot 1.3.9 要求至少 2.12.0。
- NapCat 或 SnowLuma 适配器，二选一即可。

已执行 MaiBot 1.2.0 + SDK 2.7.1 / 2.8.0、MaiBot 1.3.0 + SDK 2.12.0、MaiBot 1.3.9 + SDK 2.12.0 的官方加载与调用桥接隔离测试。SDK 上限为兼容声明，不表示已测试所有后续版本。测试使用真实 SDK 和 SQLite，QQ 与 RPC 外部通信模拟，仍需在实际启动器环境验收。
